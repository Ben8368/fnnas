# FnNAS Qualcomm maintenance boundaries

- `main`, `origin/main` and `upstream/main` must stay identical after an explicit fast-forward sync. Never commit Qualcomm work on `main`, merge Qualcomm into it, rewrite it, change the default branch, or add a dispatch shim there. Check `git status`, ancestry and full SHAs before pushing. Normal development lives on `codex/qualcomm-sm8250`.
- Do not restructure `make-fnnas/qualcomm/sm8250` or alter the Amlogic/Rockchip/Allwinner paths to accommodate Umi. Keep generic interfaces small, route Qualcomm only for an explicit supported board, and keep Debian reproduction in `tools/legacy`.
- Push development updates to the development branch when publishing source. Resolve the highest final Linux 6.18.y from Linux Stable for each build and run regressions on that exact Linux commit. Record source SHA, Linux SHA, profile, package SHA-256 and build/audit logs. CI runs are optional; when used, subscribe to outcomes and also retain Run ID and Attempt. Never infer GitHub success from a local test. Unknown patch conflicts stop the build. Skip decisions require the exact patch digest and a reason.
- Use a verified official fnOS ARM64 base for native images; a Debian Umi reproduction is not a fnOS donor. Pin the real archived byte digest, inspect the disk read-only, keep the Btrfs layout explicit, and verify the root UUID, fstab and installed module bytes and vermagic.
- Use one Umi kernel and image workflow throughout adaptation; local builds and CI are both optional sources. Record source SHA, Linux SHA, profile and package SHA-256; CI also records run and attempt. Assemble before installing. With explicit authorization and a stock DTBO preflight, install directly on the device and verify the installed system; RAM boot is not required. Record kernel, fnOS userspace and OTA results separately. Publish through the controlled local tool with physical evidence and a tag pointing to the exact source SHA.
- Build clean `pr/qualcomm-*` topic branches from `upstream/main` when requested. Keep generic routing, native image plumbing, board support and downstream-only evidence in separate review units. Audit file-level SPDX, copied code and source obligations before submitting a PR or distributing a kernel; never strip license notices.
