# FnNAS Qualcomm maintenance boundaries

- `main`, `origin/main` and `upstream/main` must stay identical after an explicit fast-forward sync. Never commit Qualcomm work on `main`, merge Qualcomm into it, rewrite it, change the default branch, or add a dispatch shim there. Check `git status`, ancestry and full SHAs before pushing. Normal development lives on `codex/qualcomm-sm8250`.
- Do not restructure `make-fnnas/qualcomm/sm8250` or alter the Amlogic/Rockchip/Allwinner paths to accommodate Umi. Keep generic interfaces small, route Qualcomm only for an explicit supported board, and keep Debian reproduction in `tools/legacy`.
- Test development updates by branch `push`. Resolve the highest final Linux 6.18.y from Linux Stable for each build and run regressions on that exact Linux commit. Subscribe to build/audit outcomes and retain Run ID, Attempt, source SHA, Linux SHA and logs. Never infer GitHub success from a local test. Unknown patch conflicts stop the build. Skip decisions require the exact patch digest and a reason.
- Use a verified official fnOS ARM64 base for native images; a Debian Umi reproduction is not a fnOS donor. Pin the real archived byte digest, inspect the disk read-only, keep the Btrfs layout explicit, and verify the root UUID, fstab and installed module bytes and vermagic. Do not publish vendor userspace or firmware until redistribution permission is confirmed.
- Only promoted kernels identified by source SHA, Linux SHA, profile, successful authorized build run/attempt, package SHA-256 and physical evidence can be consumed by the image builder. Publish via the controlled local tool, not with CI credentials. The tag must point to the exact source SHA. No flashing, repartitioning or block writes in build/CI; real hardware tests use RAM boot with stock DTBO preflight and recovery evidence, separately from native fnOS userspace/OTA acceptance.
- Build clean `pr/qualcomm-*` topic branches from `upstream/main` when requested. Keep generic routing, native image plumbing, board support and downstream-only evidence in separate review units. Audit file-level SPDX, copied code and source obligations before submitting a PR or distributing a kernel; never strip license notices.
