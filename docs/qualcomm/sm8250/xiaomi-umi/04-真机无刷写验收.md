# umi 真机验收（保留现有 Android）

此流程只验证 **ABL → Linux 内核 → RAM 诊断 PID 1 → 返回 Android**，不刷写任何分区，不挂载 Android `/data`，不能替代完整 rootfs 和外设验收。命令在 Bash 中执行；Windows 下可用 PowerShell 7.4+ 做原生二进制重定向，或选择能正确保留 `adb exec-out` 二进制输出的终端。

## 1. 在 Android 下确认面板及当前 DTBO

先用 `adb devices -l` 确认目标，读取 `/proc/cmdline` 或 `/proc/bootconfig` 的 `androidboot.oled_panel_id`、`androidboot.dtbo_idx`；记录实际的面板版本。以下以 **CSOT、index 11** 为例。禁止在 CSOT 上把 SMS 版当作等效对照。

如果设备授权 `adb root`，可以只读导出**当前** DTBO，不需要刷原厂 DTBO 来做预检：

```bash
SERIAL='<device-serial>'
adb -s "$SERIAL" root
adb -s "$SERIAL" wait-for-device
adb -s "$SERIAL" exec-out 'cat /dev/block/by-name/dtbo' > installed-dtbo.img
adb -s "$SERIAL" unroot
unpack_bootimg --boot_img /path/to/boot-umi-csot-60hz-6.18.60.img --out ./boot-check
python3 make-fnnas/qualcomm/sm8250/boot/abl-android-v2/tools/check-installed-dtbo.py installed-dtbo.img 11 boot-check/dtb --protect-live
```

这台设备的 index 11 额外引用 `pm8150a_l2`，旧版基线的 boot 预检会报缺符号。原生显示版把已知原厂符号映射到 `/abl_ovf` 的禁用节点。`--protect-live` 同时验证叠加后 Linux 硬件树没有变化。如果其他设备仍缺符号，先停止启动并确认对应 overlay。面板和外设仍需真机验证。

完整构建时也可在 `assemble-release.sh` 的四个参数后附加 `installed-dtbo.img 11`，让它在打包 boot 前校验该 overlay。

## 2. 生成诊断镜像，只用 Fastboot 临时运行

```bash
python3 make-fnnas/qualcomm/sm8250/boot/abl-android-v2/tools/make-ram-probe.py /path/to/boot-umi-csot-60hz-6.18.60.img ./branch-ram-probe.img
adb -s "$SERIAL" reboot bootloader
fastboot -s "$SERIAL" getvar product
fastboot -s "$SERIAL" boot branch-ram-probe.img
```

比较旧内核时，用同一刷新率的历史 CSOT Boot 生成另一份探针，并用 `--base-dtb` 传入**已通过同一设备 DTBO 预检**的兼容 CSOT DTB。每轮从 Android 重新进 bootloader，不要复用上一轮尝试后自动返回的 Fastboot 会话。`Booting OKAY` 之后还需检查内核日志。

探针不会初始化或挂载任何设备根盘。ACM 仅用于发送 RAM 中的诊断记录，不提供 shell（Windows `COMx` / Linux `/dev/ttyACM*`，115200 8N1，不开流控）；可在重启前保存至 `UMI_PROBE_REPORT_END`，作为 pstore 丢失时的独立证据。USB 没枚举也不会阻塞定时重启。进入诊断 PID 1 后约 35 秒尝试重启；Android 回到 ADB 还需要额外的启动时间。如果两分钟后仍未恢复，不要尝试刷写；长按电源键，松手后正常启动 Android。若确实停在 Fastboot，可执行 `fastboot -s "$SERIAL" reboot`。

## 3. 一轮一收集，分开判定

```bash
adb -s "$SERIAL" root
adb -s "$SERIAL" wait-for-device
python3 make-fnnas/qualcomm/sm8250/boot/abl-android-v2/tools/read-ram-probe-log.py "$SERIAL" branch-ram-probe-pstore.log
adb -s "$SERIAL" unroot
```

应找到本轮对应的 `Linux version`、`Run /umi-probe`、`UMI_PROBE: PID1` 及重启记录。检查 CSOT 背光读回、DSI 是否连接并启用、实际 DRM 模式是否为所选 1080×2340 @ 60Hz 或 90Hz，同时观察屏上有没有正常的横屏文字。没有日志时，检查本轮 pstore 和传输权限。分享日志前先去除机器标识。

RAM 探针也会记录 PM8150B 电源设备的在线状态、充电状态、电压和电流。可加入静态 ARM64 GPU 探针，在 RAM 中通过 MSM 渲染节点查询芯片 ID。查询成功证明 GPU 硬件初始化完成。另用同次构建、UUID 匹配的独立 Linux 根盘验收渲染负载、充电策略、USB 首启设密、Wi-Fi、Venus 和 Docker。

下面生成的镜像可用于第 2 步的临时启动。

```bash
KERNEL_WORK=/path/to/built-kernel
make -C "$KERNEL_WORK/linux" O="$KERNEL_WORK/kernel-out" ARCH=arm64 \
    CROSS_COMPILE=aarch64-linux-gnu- INSTALL_HDR_PATH="$PWD/umi-uapi" headers_install
aarch64-linux-gnu-gcc -O2 -static -I"$PWD/umi-uapi/include" \
    -o umi-gpu-check make-fnnas/qualcomm/sm8250/boot/abl-android-v2/tools/umi-gpu-check.c
python3 make-fnnas/qualcomm/sm8250/boot/abl-android-v2/tools/make-ram-probe.py /path/to/release-boot.img \
    ./branch-ram-probe-gpu.img --gpu-check ./umi-gpu-check
```
